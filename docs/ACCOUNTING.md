# Инварианты и исправления

## Единицы
Все введённые метры хранятся целым количеством миллиметров. Килограммы — целым количеством граммов.
Количество катушек — целое число. Дробные значения массы/длины допускают до 3 знаков после запятой.
Удельный вес хранится исходной парой sampleGrams / sampleMm, не округлённым десятичным коэффициентом.
Эквивалент отправки: round(grams × sampleMm / sampleGrams), целые мм. Промежуточное умножение — BigInt.

## Операции
- report/excavation: +cableMm; trenchMm — независимый счётчик работ.
- report/winding: +count по каждому типу в запасе катушек; метры намотки фиксируют обработку части существующего запаса и не увеличивают общий остаток в метрах.
- trip/dispatch: -1 катушка и -sentMm на каждую строку; +grams в пути.
- trip/receipt: +фактические grams в накопленную приёмку; полностью закрывает вес рейса в пути; difference=received-dispatched.
- opening: исходный запас; накопленные работы в отдельных полях не увеличивают запас.
- adjustment: фактический проверенный остаток минус рассчитанный остаток без текущей корректировки. Можно проверить только метры или только штуки.
- новые коэффициенты не перепроводят старые отправки.

## Метры намотки и последовательность измерений

Метры — основная единица первичного измерения; штуки катушек — дополнительный показатель производительности. Временная площадка входит в тот же ПИД, что поле; перемещение между ними не является отправкой на склад.

В начальной записи `mm` — весь извлечённый кабель, ещё не отправленный с ПИД, включая намотанный. `coils` — катушки с частью этого же кабеля. `woundMeasurement` описывает именно эти начальные катушки, а не сегодняшние остатки. `accumulatedWoundMm` — весь ранее намотанный метраж независимо от местонахождения; он не прибавляется к запасу.

У строки отчёта намотки `measurement` и у начальных катушек `woundMeasurement` хранится одна структура:

- `directMm`: измеренная длина либо null, если ещё неизвестна;
- `grams`: масса всей указанной партии без тары либо null;
- `weighedOn`: фактическая дата взвешивания либо null;
- `coefficient`: сохранённые ID/версия и исходная пара длины и массы контрольного отрезка либо null;
- `calculatedMm`: длина по весу, рассчитанная сервером, либо null.

Дата взвешивания может быть позже даты начального остатка или намотки. Для нового взвешивания используется контрольный замер не позднее даты взвешивания. При открытии сохранённого взвешивания его коэффициент не подменяется новым замером. Для отчёта дата взвешивания не может быть раньше намотки. Прямые измерения сохраняются отдельно от расчётных; обе величины доступны в истории.

В показателе метража намотки учитывается `directMm`, если он известен, иначе `calculatedMm`. Неизвестный метраж не выводится из количества катушек или из всего извлечения. Итог сопровождается количеством катушек без уточнённой длины. Сохранение уточнения создаёт новую версию исходной записи, не добавляет повторно катушки и не меняет общий запас в метрах.

Старые документы без новых полей остаются действительными. Их длина намотки считается неизвестной; исходные остатки и расчёты отправок сохраняются. Открытый до обновления клиент не может молча стереть новые измерения. Изменение количества катушек таким клиентом при наличии измерений требует обновить приложение.

Расчёт по весу может отличаться от прямого измерения. Расхождение отображается, но не создаёт автоматической поправки к общему остатку. Начальную длину кабеля в катушках, измеренную напрямую, нельзя задать больше общего начального запаса на ПИД. Начальный ПИД и тип нельзя переназначить существующей записи.

## История
SQLite documents append-only: UNIQUE(namespace, document_id, version), UNIQUE(namespace, request_key).
Автор исходного документа и редактор последней версии раздельны.
Актуальная версия вычисляется по MAX(version); старые версии доступны для аудита.
Ключ суточного отчёта: автор + ПИД + дата + категория. У разных прорабов записи различаются.
Оптимистическое обновление: INSERT новой версии только если предыдущая версия ещё актуальна.
Повторный requestKey с тем же содержимым возвращает прежний результат, с другим содержимым — ошибка.
Корректировка дополнительно проверяет, что между расчётом и сохранением не появились конкурирующие записи того же ПИД.

## Пример: поздняя намотка
Начало 5; отправили 8 → -3. Никакого автоматического восстановления.
Намотчик внёс запоздавшие 3 → 0.
Если администратор ранее по проверке создал корректировку, поздняя запись не удаляет её; она отмечается для повторного рассмотрения.
Изменение корректировки — новая версия с основанием. Производственный объём не меняется от корректировки.

## Авторизация
Demo разрешён только при APP_MODE=demo и доверенном идентификаторе владельца из приватной платформы.
Production разрешён только по проверенному HMAC Telegram initData и существующей активной записи пользователя.
Не доверять initDataUnsafe, x-demo-user в production, роли из тела запроса или первому посетителю.
Bot API token используется только сервером. В БД и исходниках его нет.
