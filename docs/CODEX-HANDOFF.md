# Продолжение разработки

Актуализировано 09.09.2026. Рабочий проект — `pid-cable`.

## Согласованная модель

Правила версии 2 описаны в ACCOUNTING.md. Поздние решения пользователя имеют приоритет над прежними REQUIREMENTS.md и обсуждениями.

- ПИД: поле и временная площадка внутри ПИД, остаток извлечённого кабеля в метрах.
- Основной склад: масса кабеля без тары в килограммах с сохранением ПИД происхождения.
- Начальные остатки подтверждаются один раз по двум местам. Без начального транзита, катушек и накопленных показателей производства. Ввод старых первичных операций вместо начального остатка отменён.
- Все прежние катушки к началу учёта находятся на основном складе; начальный вспомогательный счётчик катушек ПИД равен нулю.
- Намотка меняет только вспомогательный учёт катушек и производительность.
- Отгрузка сохраняет массу каждой катушки; из неё и закреплённого контрольного замера рассчитывается расход метров с ПИД. В пути учитывается масса.
- Приёмка сохраняет отдельное фактическое взвешивание, закрывает весь отправленный вес из транзита и выделяет разницу. Частичная приёмка или приёмка без веса каждой катушки пока не поддерживается.
- Исправления сохраняют историю и причину; журнал формирует обратные записи и новую версию одной транзакцией.

## Размещение

Рабочий адрес: https://serfroll-rssdemontage-3c31.twc1.net/ . Telegram: https://t.me/rsskablebot . Вход в рабочую версию — из Telegram.

Исходники: публичный репозиторий `SERFROLL/RSSdemontage`, remote `github`. Изменения отправляются в `main`; GitHub Actions проверяет логику, API, PostgreSQL 18, типы и контейнер, затем продвигает `release`. Timeweb App Platform следит за `release`.

Старый remote `origin` и конфигурация Sites сохранены для совместимости. Пользователь выбрал размещение в Timeweb: не переключать хостинг самостоятельно.

Timeweb: приложение 251075, проект 2903111, PostgreSQL 4207675, приватный S3 для аудио. Новые серверы для версии 2 не требуются. Секреты находятся в окружении приложения; не включать их в код, журнал инструментов или документацию.

`BOT_ENABLED=false`: автоматические сообщения и webhook не включать без дальнейшего задания. Поле проверки доступности Timeweb оставлено пустым из-за ранее наблюдавшегося зависания проверки провайдера; приложение выполняет проверку при запуске, внешний `/api/health` доступен.

## Проверки и данные

Локальные тесты работают только на изолированных данных; PostgreSQL-тест допускает только локальную отдельную базу `pid_cable_test`. Не запускать тестовые сценарии против рабочей базы.

Переход сохраняет старые источники и переносит их версии в журнал без изменения количеств. Не выдавать отсутствующую историческую массу склада за известный ноль. Для уточнения старых остатков предусмотрена отдельная корректировка выбранного места.

Поздние изменения отчётов, рейсов, начальных остатков и других более ранних корректировок помечают последующие сверки для повторной проверки. Значения ранее подтверждённых корректировок автоматически не переписываются.

Резервная копия `/api/backup` формата 2 содержит источники и нормализованный журнал. Аудиофайлы хранятся отдельно в S3. Перед миграцией 09.09.2026 создана ручная логическая копия базы Timeweb.

Мобильная проверка выполняется по готовой сборке Timeweb. Важная защита диалога на телефонах: явные нулевые `--tw-translate-x` и `--tw-translate-y`; сокращённые CSS-преобразования могут исчезнуть после минификации. Не удалять эту защиту.

## Сопутствующие функции

Выгрузка Excel для 1С сохраняет прежние ID и версии строк; добавленные катушки ранее выгруженного рейса и удаления попадают в следующую выгрузку независимо от её периода. Сам файл не означает загрузку в 1С. Подключение к конкретной конфигурации 1С остаётся отдельной задачей.

Руководство сотрудника и ИИ: `outputs/Демонтаж_кабеля_руководство_для_сотрудника_и_ИИ.md`. Оно описывает функции и порядок ввода, но не содержит рабочие остатки и не предоставляет другому ИИ доступ к базе.
