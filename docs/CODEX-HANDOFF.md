# Продолжение разработки в Codex

Дата: 08.09.2026.

## Восстановленный контекст

Источник — чат ChatGPT «Отчет о демонтаже кабеля» и исходники опубликованного приложения.
Требования находятся в REQUIREMENTS.md; правила расчётов — в ACCOUNTING.md; условия запуска — в PILOT.md.
При расхождениях учитывать поздние решения: единый Mini App, корректировка по проверенному фактическому остатку, полный вывод принятого рейса из «В пути» независимо от разницы весов.
Старые предложения о вводе чисел в чате и автоматическом восстановлении до нуля отменены.

Существующий стенд: https://pid-cable.esenprokop.chatgpt.site.
Его исходники получены из привязанного репозитория. Начатая до получения контекста папка `cable-telegram` — отдельная неиспользуемая заготовка; рабочий проект — `pid-cable`.
Секреты из переписки в этот документ и исходники не перенесены.

## Исправление выгрузки

После выгрузки отправки из четырёх катушек сотрудник добавляет пятую.
Следующая выгрузка за другой период прежде содержала только четыре старые строки: новая строка не имела предыдущего экспортного ID.
Теперь новые строки ранее выгруженной операции включаются вместе с исправлениями и в лист «Изменения».
Повторная выгрузка без новых исправлений за другой период их не включает.
Исторические операции, которые ещё не выгружались, по-прежнему отбираются по выбранному периоду.

Проверка воспроизвела ошибку до исправления: 4 строки вместо 5.
После исправления: 26 проверок предметной логики и 12 проверок реальных API-обработчиков на SQLite прошли.

## Следующие задачи

1. Приоритет пользователя — удобство экранов и ввода с телефона. ID администратора получен и сохранён в локальной папке outputs, подключение отложено.
2. Проверить цепочки корректировок остатков: сейчас adjustmentReviews отслеживает поздние отчёты, рейсы и начальные остатки, но не изменение другой корректировки. До пилота проверить сценарий изменения ранней корректировки после более поздней инвентаризации.
3. Провести согласованную проверку форм с телефона, включая голосовое пояснение и продолжение незавершённой приёмки.
4. Настроить рабочий HTTPS-доступ, отдельное рабочее хранилище, администратора и пилотный ПИД.
5. Затем подключить Telegram, группу и расписание. Реальные сообщения и webhook в этой задаче пока не включались.

Для подключения требуются проверенный числовой Telegram ID администратора, ID общей группы, участники и начальные данные пилота. Токен повторно в переписку не запрашивать.
Загрузка документов в 1С:УНФ остаётся отдельной задачей после уточнения существующего формата импорта.

## Мобильные экраны

Нижняя навигация, полноэкранная форма с отдельной прокруткой и закреплёнными действиями, крупные поля отчёта, числовая клавиатура для количества катушек.
Приёмка представлена карточками с номером, типом, отправленной и принятой массой; видны прогресс и общий принятый вес, есть переход к следующей невзвешенной катушке.
Дата ранее подтверждённого отчёта и отправки показана без редактирования, в соответствии с существующей логикой.
Запуск Telegram SDK учитывается до первого запроса данных. Изменение полей выдаёт новый ключ операции, а повтор неизменённого запроса сохраняет прежний.

Зависимости установлены по package-lock.json. Проверка типов, сборка Vinext и 38 автоматических проверок прошли в Windows.
Визуальное тестирование браузером и проверка на физическом телефоне пока не выполнялись.
