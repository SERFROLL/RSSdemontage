# GitHub и автоматические обновления

## Подготовлено

В `.github/workflows/ci.yml` настроены проверки при push, pull request и ручном запуске:
установка по package-lock.json, расчётные и API-проверки, TypeScript, сборка.
Проверки не требуют токена Telegram, доступа к рабочей базе или секретов хостинга.
Этот workflow не публикует приложение и не меняет Telegram.

## Подключение репозитория

Репозиторий собственника: https://github.com/SERFROLL/RSSdemontage. По решению собственника от 08.09.2026 он остаётся публичным.
Для него используется отдельный remote `github`; существующий `origin` проверочного стенда сохраняется.
В репозиторий входят исходники и тестовые данные. Секреты, рабочие данные и локальные файлы из `outputs` остаются за его пределами.
После первой загрузки следует дождаться успешного запуска App checks в разделе Actions. Локальная проверка не равна выполненному запуску на GitHub.

## Timeweb

Текущий код использует Cloudflare Worker, D1 и R2. Перед публикацией на Timeweb требуется адаптация серверного запуска, доступа к БД и аудиохранилищу, а также настройка расписания.
GitHub Actions пока проверяет существующую сборку Cloudflare; успешный результат не означает готовность этой сборки к Timeweb.

Для обновления только после успешных проверок нужно связать публикацию с результатом CI: например, запускать деплой через отдельную задачу после verify либо подключить Timeweb к ветке выпуска, которая обновляется только проверенными версиями.
Простое включение автодеплоя каждого push не гарантирует ожидание GitHub Actions.

Рабочая БД и аудио хранятся отдельно от обновляемого кода. Доступы задаются в секретных настройках хостинга, резервные копии настраиваются отдельно.
