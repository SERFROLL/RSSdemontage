# План пилота и критерии

## Порядок
1. Проверка правил и расчётов — до подключения живых сообщений.
2. Единый Mini App на тестовых данных — проверка с телефона.
3. Приватное сохранение исходников и проверочного стенда.
4. Выбор рабочего HTTPS-хостинга и проверенный Telegram ID владельца.
5. Назначение сотрудников, ввод ПИД/типов/замеров и начальных остатков.
6. Подключение бота, группы и расписания.
7. Пилот на одном ПИД, затем остальные.

## От собственника сейчас
Открыть стенд; проверить прораба, намотчика, отправку и приёмку в тестовых ролях.
До рабочего включения: числовой Telegram ID администратора, состав пилота, начальные остатки, адрес/размещение, ID общей группы.
Не покупать сервер до выбора схемы размещения. Токен уже проверен; повторно в чат его не отправлять.

## Проверить руками на телефоне
- У прораба два ПИД, разные запросы, дата не теряется.
- Два поля с числовой клавиатурой; проверка и подтверждение.
- Выходной/простой без чисел, пояснение голосом.
- Намотка двух типов в штуках.
- Отправка: 123 234 345 456 = четыре катушки, 1 158 кг.
- Приёмка в порядке 3, 1, 4, 2; недовес не мешает закрыть рейс.
- Закрыть незавершённую форму и продолжить на том же устройстве.
- Исправить свой прошлый отчёт, увидеть прежнюю версию.
- Показать отрицательный расчётный остаток; добавить поздний отчёт.
- Проверить корректировку на фактический остаток и повторную проверку после позднего отчёта.
- Выгрузить файл, затем исправить прошлую отправку и выгрузить текущий период.

## Подготовлено в коде, но не включено на стенде
POST /api/telegram — webhook с отдельным секретом.
POST /api/scheduler — защищённый запуск расписания. На рабочем хостинге вызывать раз в минуту.
GET /api/backup — администраторская резервная выгрузка журнала документов.
APP_MODE=production — проверка Telegram initData и списка сотрудников.
scripts/telegram-setup.mjs — настройка webhook и меню; проверяет существующий webhook перед заменой.

## Готовность к рабочему запуску
Отдельная production БД, проверенный администратор, актуальные начальные данные, HTTPS, доступность с телефонов сотрудников, испытание уведомлений по Красноярску, проверка восстановления резервной копии.
Исходники Telegram-части не означают, что расписание уже включено.
