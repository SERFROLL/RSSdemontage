# Рабочий учёт TG / WEB

Новый учёт включается только после загрузки проверенного пакета истории. `/tg` и `/web` используют одну PostgreSQL БД и одни права. Старые таблицы не изменяются и не удаляются.

## Данные

- Склад принадлежит МОЛ; полевой склад дополнительно связан с ПИД. Несколько кабелей учитываются раздельно внутри склада.
- Метры извлечения переводятся в тонны по подтверждённым г/м. В журнале масса записана целыми граммами, катушки — отдельной единицей. Копка и намотка не меняют массу.
- Отправка переносит материал со склада в путь; приёмка — на склад получателя. Расхождение масс остаётся отдельным остатком до выяснения.
- Разделка погашает кабель и создаёт взвешенные металлы. Невзвешенный отход не является номенклатурой. Тариф и норматив фиксируются в версии документа, КТУ распределяет ФОТ с точностью до копейки.
- Матрица назначений создаёт задания в 09:00 по Красноярску, все календарные дни. Созданные задания сохраняют снимок функций, МОЛ и доверенных лиц. Авторы ввода записаны отдельно.
- Восстановленная история отмечена `source=restored`; она участвует в остатках и выработке, но исключена из дисциплины сдачи заданий. Коэффициенты применены ретроспективно с сохранением настоящих дат подтверждения.

## Сохранение и защита

Сервер заново проверяет команду и вычисляет результат. Предлагаемые браузером остатки, авторы, права, тарифы, коэффициенты и время не являются доверенными данными. Одна транзакция сохраняет документ, историю, обратные проводки прежней версии и новые проводки. PostgreSQL блокировка и номер редакции защищают параллельный ввод. Ключ запроса защищает повторное нажатие и повтор после сетевого обрыва.

WEB получает семидневный HttpOnly-сеанс после ввода восьмизначного кода в Telegram-приложении. Код одноразовый, действует пять минут. Подпись Telegram проверяется сервером; постоянные пароли и почтовый сервер не используются. Изменение доступа закрывает старые WEB-сеансы сотрудника.

## Переключение

1. Сборка проходит тесты, TypeScript, оба варианта сборки и Linux-контейнер с настоящим PostgreSQL.
2. Временный `/api/operational/bootstrap` разрешает только один пакет с заранее заданным SHA-256 и одноразовым секретом, до установленного срока. Секрет и данные сотрудников в Git не хранятся.
3. До импорта скачивается резервная копия старых таблиц. Транзакция импорта дополнительно сохраняет их в `operational_backups` и проверяет контрольные массы и равенство сторон журнала.
4. После импорта главный адрес открывает новый интерфейс; прежние API закрыты для записи. Повтор того же пакета ничего не добавляет.
5. После завершения переключения срок временного доступа закрывается отдельным коммитом. Обычная резервная копия доступна администратору WEB через настройки доступа.

## Откат

До новых рабочих записей можно вернуть прежний проверенный коммит контейнера: старые таблицы сохранены. Альтернатива — `OPERATIONAL_ROLLBACK=true`: главный адрес открывает прежний учёт, новые API блокируются. Это переключение интерфейса, а не удаление новой истории.

Если после запуска уже появились рабочие документы, сначала выгрузить резервную копию нового учёта. Нельзя считать откат контейнера переносом этих документов в старую схему: старый учёт не поддерживает склады МОЛ + ПИД. Для дальнейшей работы требуется либо исправление новой версии, либо отдельный согласованный перенос новых операций.

## Проверки

`node scripts/test-operational.mjs` проверяет права, двойной ввод, нормы по кабелям, пересчёт истории и расшифровки. С `TEST_DATABASE_URL` проверяет настоящий PostgreSQL, конкуренцию, откат транзакции и авторизацию WEB. Тесты допускают только локальную отдельную БД `pid_cable_test`.

`OPERATIONAL_IMPORT_FILE` добавляет контроль приватного пакета истории без публикации файла. `scripts/prepare-operational-import.py` создаёт пакет из согласованных локальных исходников; результат нельзя добавлять в Git.
